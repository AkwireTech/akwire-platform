Cloud & Virtualization Security Architecture

Cloud and virtualized environments change where systems run, but security responsibilities remain. Secure architecture requires understanding the environment, protecting workloads, and controlling access to cloud resources.

CLOUD SECURITY ARCHITECTURE
CLOUD SECURITY

Security Follows the Workload

Cloud computing changes the location and ownership of infrastructure. Systems may run on infrastructure managed by a cloud provider, while the organization remains responsible for securing its data, identities, configurations, and workloads according to the service model.

Visibility Know what resources exist, who can access them, and how they communicate.
Secure Configuration Misconfigured cloud resources can expose data and services even when the underlying infrastructure is secure.
CLOUD SERVICE MODELS

Security Responsibilities Depend on the Service

IaaS Infrastructure as a Service

The provider supplies foundational infrastructure while the customer has greater responsibility for operating systems, applications, configurations, and data.

PaaS Platform as a Service

The provider manages more of the underlying platform while the customer focuses primarily on applications, configurations, and data.

SaaS Software as a Service

The provider manages the application platform and infrastructure while the customer remains responsible for users, access, configuration, and data use.

Cloud security follows a shared-responsibility model: the provider and customer each have defined security responsibilities.
VIRTUALIZATION

Multiple Workloads Can Share One Host

Virtualization allows multiple virtual machines or workloads to operate on a shared physical host. A hypervisor provides the abstraction and isolation between the virtualized environments.

Security depends on maintaining strong isolation and protecting the hypervisor and virtual workloads.
CLOUD NETWORK SECURITY

Control Traffic Between Cloud Resources

Public Access Internet-facing resources
Security Boundary Policies and traffic controls
Private Resources Protected workloads and data
Cloud resources should receive only the network access required for their function.
CLOUD DATA PROTECTION

Protect Data at Rest and in Transit

Cloud storage can contain sensitive organizational information. Security architecture should address access, encryption, configuration, backup, and lifecycle requirements.

Encryption can help protect data from unauthorized disclosure while access controls determine who can use the data.
CLOUD THREAT CONTAINMENT

Isolate Compromised Workloads

Compromised Workload Suspicious activity detected
Isolation Restrict access and communication
Protected Resources Reduce further exposure
MEMORY CHECK

Remember the Cloud Security Model

MODEL Know the service model
RESPONSIBILITY Know who secures what
CONFIGURE Secure resources and access
PROTECT Limit exposure and impact
UNDERSTAND Know the cloud service and deployment model
ASSIGN Understand shared security responsibilities
PROTECT Secure identities, workloads, networks, and data
KEY TAKEAWAY Moving workloads to the cloud does not eliminate security responsibility. Identify the service model, understand the shared responsibility boundary, secure configurations and identities, protect data, and isolate compromised workloads when necessary.
