Cloud Security Controls & Shared Responsibility

Cloud security depends on understanding who secures what, where controls are applied, and how those controls protect identities, workloads, networks, and data.

THE SECURITY QUESTION

Who is responsible for security?

Moving a workload to the cloud does not transfer every security responsibility to the provider.

CONTROL RESPONSIBILITY The service model changes the security boundary.
IaaS Infrastructure as a Service
PROVIDER Physical infrastructure
CUSTOMER OS, applications, data, access
PaaS Platform as a Service
PROVIDER Infrastructure and platform
CUSTOMER Applications, data, identities
SaaS Software as a Service
PROVIDER Application and infrastructure
CUSTOMER Users, access, data, configuration
CONTROL 01 Identity & Access
Identity Who is requesting access?
Authentication Prove the identity.
Authorization What can it access?
Audit Record the activity.
CONTROL 02 Protecting Cloud Data
DATA AT REST Protect stored information. Encryption
DATA IN TRANSIT Protect information moving between systems. Secure protocols
DATA IN USE Protect information while being processed. Access controls
CONTROL 03 Secure Configuration
Least Privilege Give identities only the access they require.
Network Segmentation Separate workloads and limit unnecessary paths.
Logging & Monitoring Detect and investigate security-relevant activity.
Secure Defaults Reduce exposure through deliberate configuration.
CLOUD SECURITY SCENARIO A storage resource is accidentally exposed.
Cloud Storage Sensitive information stored
Public Access Configuration exposes the resource
Corrective Control Restrict access and verify configuration
Cloud security failures often come from misconfiguration—not a failure of the underlying cloud infrastructure.

EXAM MEMORY

Cloud security is shared responsibility.

Always determine the service model first, then identify which security controls belong to the provider and which remain with the customer.
