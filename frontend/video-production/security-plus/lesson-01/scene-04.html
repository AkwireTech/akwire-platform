Security Principles & Zero Trust

Explore least privilege, need to know, separation of duties, and the Zero Trust approach to protecting modern systems.

Security Fundamentals
SECURITY PRINCIPLES

Give Access Carefully

Strong security does not mean giving every user unrestricted access. Organizations limit access according to business requirements, job responsibilities, and the sensitivity of the information being protected.

Least Privilege Give only the access required to perform a task.
Need to Know Access information only when the job requires it.
SECURITY PRINCIPLE 01

Least Privilege

Minimum Access

Users receive only the permissions necessary to perform their assigned responsibilities.

EXAMPLE Read-only instead of administrator access
Reduce Impact

Limiting permissions reduces the potential damage caused by compromised accounts or mistakes.

BENEFIT Smaller attack surface
Review Access

Permissions should be reviewed and adjusted when responsibilities change.

PRACTICE Remove unnecessary privileges
SECURITY PRINCIPLE 02

Need to Know

Need to know limits access to specific information based on whether a person actually requires that information to perform a legitimate task.

A user may have access to a system without needing access to every piece of information stored inside it.
SECURITY PRINCIPLE 03

Separation of Duties

Approval

One person may request or initiate a sensitive action.

Execution

Another authorized person performs or completes the action.

Reduce Abuse

Dividing responsibilities helps reduce fraud, mistakes, and conflicts of interest.

SECURITY PRINCIPLE 04

Zero Trust

Zero Trust is a security approach based on the idea that access should not be automatically trusted simply because a user, device, or connection is inside a network boundary.

Verify identity and security context, enforce least privilege, and continuously evaluate access.
ZERO TRUST MODEL

Never Trust Automatically

Verify

Confirm identity and evaluate the request before granting access.

Least Privilege

Grant only the access required for the requested task.

Assume Breach

Design security controls with the expectation that compromise can occur.

MEMORY CHECK

Core Security Principles

KEY TAKEAWAY Strong security limits access to what users need, separates sensitive responsibilities, and avoids automatic trust. Least privilege, need to know, separation of duties, and Zero Trust work together to reduce unnecessary access and limit the impact of a compromise.
